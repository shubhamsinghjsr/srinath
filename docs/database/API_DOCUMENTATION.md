# API documentation

Base URL: `http://localhost:4000/api/v1`. Success responses use `{ "data": ... }`; errors include an error message and validation details where relevant. Protected routes require `Authorization: Bearer <JWT>`. Platform routes also require the `SUPER_ADMIN` role. Institutional JWT scope is reloaded from the database on each request.

## Health and authentication

| Method/path | Description |
|---|---|
| `GET /health` | API liveness only. |
| `POST /auth/login` | Platform sign-in, body `{email,password}`; rate limited. |
| `POST /auth/institutional-login` | University sign-in, body `{universityCode,email,password}`; rate limited. |
| `GET /auth/me` | Returns current account, roles and institutional scope. |
| `POST /auth/logout` | Revokes the current login-log session. |

Passwords use bcrypt hashes. Session revocation is checked against platform or institutional login history. Failed login attempts are logged.

## Platform dashboard

- `GET /platform/dashboard/overview`: counts and subscription status totals.
- `GET /platform/dashboard/university-statistics?months=12`: registration chart (1–36 months).
- `GET /platform/dashboard/subscriptions`: status totals and latest subscription rows.
- `GET /platform/dashboard/recent-activities?limit=20`: platform audit history (limit 1–100).
- `GET /platform/dashboard/system-health`: central PostgreSQL and tenant database status.

## University management

- `GET /platform/universities?q=&status=&type=&page=1&limit=20&sortBy=createdAt&sortOrder=desc`: search and pagination, max 100/page.
- `POST /platform/universities`: creates a university and profile relations; multipart form can include `logo`.
- `GET /platform/universities/:id`: retrieves profile and non-secret tenant status.
- `PUT /platform/universities/:id`: updates profile relations; optional replacement logo.
- `PATCH /platform/universities/:id/status`, `POST /:id/activate`, `POST /:id/suspend`: status changes.
- `DELETE /platform/universities/:id`: soft-deactivation; does not delete its records.
- `POST /platform/universities/:id/users`: creates institutional user. Body `{name,email,password,campusId?,collegeId?,roleCodes[]}`. All referenced scope and roles must belong to the university. Password is hashed and never returned.
- `GET /platform/universities/:id/campuses`: lists campus records owned by that university.
- `POST /platform/universities/:id/campuses`: creates a campus under the path university. Body `{name,code?,campusType,city?,addressLine?,status?}`. Blank code is generated by the API; duplicate codes return 409.

University profile accepts `type` (`CENTRAL|STATE|PUBLIC|PRIVATE|DEEMED|AUTONOMOUS|OTHER`), name, website, official email/contact, legal/registration details, address, accreditation and branding fields. The full field names are validated by `backend/src/validation/university.schema.ts`.

Legacy optional provisioning routes are `POST /platform/universities/:id/provision-database`, `GET /:id/database-status`, and `POST /:id/verify-database`. They use `POSTGRES_ADMIN_URL`; these are not required for the shared-database tenant architecture and should not be enabled until that choice is reviewed.

## Tenant-scoped ERP record API

These endpoints use the flexible `erp_records` table for module-specific entries. Institutional scope is read from the signed session; caller-provided tenant IDs cannot widen access. A platform user must include the target `universityId`.

| Method/path | Description |
|---|---|
| `GET /erp/records?universityId=&moduleCode=&status=&q=&page=1&limit=20` | Paginated scoped search. |
| `POST /erp/records` | Creates `{moduleCode,recordType,name,referenceCode?,category?,status?,payload?,universityId?,campusId?,collegeId?,academicSessionId?}`. Tenant identity for institutional users is taken from JWT. |
| `GET /erp/records/:id?universityId=` | Retrieves a record only when it is inside caller scope. |
| `PATCH /erp/records/:id?universityId=` | Updates record data after tenant reference checks. |
| `DELETE /erp/records/:id?universityId=` | Archives by changing status; does not physically delete. |

The Super Admin's generic module Add/list flow is connected to this API once a university is selected in the workspace. The normalized domain schema exists for academic, HR, student, examination, finance, library, facilities, LMS, research, placement, support and other areas. Dedicated CRUD services, edit/archive controls and frontend integration for every normalized module remain unfinished; the flexible API is not a substitute for those workflows.

## Signed aggregate metrics

`POST /tenant-metrics` is for a trusted tenant agent, not browser code. JSON body `{students,faculty,campuses}` and headers `X-Tenant-Code`, `X-Timestamp` (Unix seconds), `X-Signature` (hex HMAC-SHA256). Signature input is UTF-8 `timestamp.CODE.students.faculty.campuses`, using uppercase code, keyed by `TENANT_METRICS_INGEST_SECRET`. Timestamp age is limited to five minutes. Do not place this secret in frontend code.
